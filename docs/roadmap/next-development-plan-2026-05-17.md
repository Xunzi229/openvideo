# OpenVideo 下一阶段开发计划书

**日期：** 2026-05-17  
**范围：** Android 本地视频播放器 OpenVideo 的产品与工程路线图  
**目标版本建议：** v0.1.0 ～ v0.5.0  
**Phase 细化目录：** [`docs/roadmap/phases/README.md`](./phases/README.md)

## 1. 项目现状总览

OpenVideo 当前已经不是「最小播放器」，而是一个以 Media3/ExoPlayer 为核心、围绕本地媒体库和沉浸式播放体验持续打磨的 Android 视频播放器。代码结构较清晰：`core` 承载播放器、偏好、字幕、更新和诊断；`data` 承载 MediaStore 扫描、Room 数据库和仓库层；`ui` 承载首页、文件夹、播放页、播放列表、隐私、设置等业务界面。

### 1.1 已具备的产品能力

| 模块 | 已有能力 | 价值判断 |
|------|----------|----------|
| 本地媒体库 | 扫描系统视频、增量刷新、加载进度、搜索、筛选、排序、网格/列表展示 | 已接近可日常使用，下一步应补齐「媒体信息组织」和「稳定索引」 |
| 文件夹浏览 | 本地文件夹聚合、文件夹内视频列表、剧集排序、继续播放 | 适合本地剧集场景，但还缺少海报、合集、命名识别 |
| 播放器核心 | Media3 ExoPlayer、硬/软解倾向、FFmpeg 音频扩展、缓冲策略、后台播放、MediaSession/通知 | 底座较扎实，下一步可做性能、错误恢复和设备兼容矩阵 |
| 播放交互 | 横竖屏布局、锁屏、手势亮度/音量/seek、双击、长按倍速、PiP、截图、AB 循环、片段导出 | 交互密度高，需从「功能多」进一步走向「手感稳定」 |
| 字幕 | SRT/VTT/ASS 解析、外部字幕选择、自动加载、编码识别、延迟、样式、位置 | 已有基础，下一步重点是在线字幕、双字幕、ASS 样式完整度 |
| 音频 | 音轨选择、音频延迟、声道、音量增强、均衡器、蓝牙/软件解码兼容方向 | 和竞品相比已有不错基础，缺少音轨语言偏好和音频问题诊断 UI |
| 播放记忆 | 历史、进度、继续观看、播放结束策略、列表连续播放 | 已能支撑追剧/续播，需要更稳定的文件身份和跨目录迁移策略 |
| 播放列表/收藏 | 收藏、播放列表、快速播放列表、批量操作 | 基础可用，下一步可增强重排、智能列表、导入导出 |
| 隐私与设置 | 隐私文件夹、通知设置、播放器分组设置、主题/语言、开源许可、检查更新 | 基础完整，下一步是隐私锁、安全入口、设置备份迁移 |
| 工程质量 | Hilt、Room、单元/源码测试、Release 脚本、崩溃日志与脱敏 | 项目已形成可持续迭代的工程习惯 |

### 1.2 当前优势

1. **手势和播放页细节投入明显。** 当前播放器已经覆盖锁屏、HUD、横竖屏差异、PiP、后台通知、AB 循环、截图等高频播放器功能。
2. **配置面丰富。** `PlayerPrefs` 已覆盖播放、画面、音频、字幕、手势、片段、书签等偏好项，说明后续做「设置导入导出」和「配置预设」有天然基础。
3. **工程拆分方向正确。** 大量 `Policy` 类和对应测试把复杂交互从 Activity 中剥离出来，适合继续推进 PlayerActivity 瘦身。
4. **本地播放器定位清晰。** README 里的初心是「好看、免费、自己喜欢的播放器」，这决定了路线不应盲目做泛视频平台，而应优先成为一款漂亮、稳定、无广告、隐私友好的本地播放器。

### 1.3 主要短板

1. **播放器页仍是复杂核心。** `PlayerActivity` 仍承担初始化、交互、字幕、通知、手势、生命周期、画面变换等大量职责；继续拆分是后续大功能稳定落地的前提。
2. **媒体库缺少「内容理解」。** 目前更多是文件级浏览，缺少电影/剧集识别、海报、演员、季集、观看状态聚合等信息架构。
3. **网络与云端能力尚未产品化。** Manifest 已有网络权限，偏好里有 `lastStreamUrl`，但还没有完整的打开 URL、局域网/NAS、WebDAV/SMB、DLNA 等入口。
4. **字幕生态还有增长空间。** 本地字幕基础好，但缺少在线字幕搜索/下载、双字幕、OCR/内嵌字幕呈现增强、字幕语言偏好。
5. **兼容性需要体系化。** 已有崩溃日志和设备兼容工具，但缺少面向真实机型/编码/容器/字幕的回归矩阵。
6. **品牌与视觉资产还弱。** 当前有深色设计稿和播放器 UI，但还缺统一品牌视觉、启动图标、空状态插画、商店截图、官网/发布页。

## 2. 竞品参考与启发

本节参考 2026-05-17 调研到的公开资料。

### 2.1 VLC for Android

VLC 的核心启发是「格式/来源全覆盖 + 完全免费无广告」。Google Play 页面显示它支持本地文件、网络流、网络共享、DVD ISO、字幕、多音轨、自动旋转、比例调整，以及亮度/音量/seek 手势。对 OpenVideo 的启发：短期不用追求 VLC 的全能，但应把「打开 URL / 网络共享 / 字幕与音轨稳定性 / 无广告隐私」作为可信赖播放器的基本盘。

来源：https://play.google.com/store/apps/details?id=org.videolan.vlc

### 2.2 MX Player

MX Player 的核心启发是「移动端手势体验和字幕操作」。其公开页面强调硬件加速、多核解码、捏合缩放/平移、字幕手势、隐私文件夹和儿童锁。对 OpenVideo 的启发：下一阶段最值得借鉴的是 **pinch-to-zoom + pan**、字幕上/下移动和字号手势、儿童锁/强化锁屏，以及更可解释的解码模式。

来源：https://play.google.com/store/apps/details?id=com.mxtech.videoplayer.ad

### 2.3 Just Player

Just Player 是与 OpenVideo 技术路线最接近的参照：同样基于 Media3/ExoPlayer，强调轻量、无广告、Android TV、FFmpeg 音频、HDR、DASH/HLS/RTSP、PiP、手势、音轨/字幕选择、帧率匹配、MediaSession、耳机断开暂停等。对 OpenVideo 的启发：如果继续坚持 Media3 路线，应优先补 **自适应流、RTSP、Android TV/遥控、自动帧率匹配、耳机/蓝牙策略、默认音轨语言**。

来源：https://github.com/moneytoo/Player

### 2.4 mpv-android

mpv-android 的核心价值是高质量渲染、libass 字幕、双字幕、网络流、后台播放、PiP、键盘输入与高级渲染参数。对 OpenVideo 的启发：不必直接迁移到 libmpv，但可以把 **高级字幕、双字幕、高质量缩放/去色带/插帧类选项、键盘/遥控快捷键** 作为专业用户方向。

来源：https://github.com/mpv-android/mpv-android

### 2.5 Infuse

Infuse 的核心启发是「漂亮媒体库 + 多来源聚合 + 元数据」。它强调自动拉取元数据、海报、演员、评分、预告片，支持 NAS、云盘、Plex/Emby/Jellyfin，支持 OpenSubtitles、Trakt、跳过片头片尾、iCloud 同步和家长控制。对 OpenVideo 的启发：长期差异化不在播放按钮本身，而在 **本地媒体库体验、剧集识别、海报墙、继续观看、跨设备/跨来源进度**。

来源：https://firecore.com/infuse

### 2.6 Kodi / Nova

Kodi 代表「客厅媒体中心」路线，强调电视遥控、电影/剧集库、PVR、插件、皮肤和网络来源；Nova 则代表开源 Android 媒体库播放器，包含 Video UI、MediaLib、文件管理和 FFmpeg 内核，并依赖 TMDb/Trakt 做刮削和同步。对 OpenVideo 的启发：如果未来进入电视/平板/NAS 场景，媒体库、遥控器、元数据、插件化会比单纯播放器控件更重要。

来源：https://kodi.tv/about/  
来源：https://github.com/nova-video-player/aos-AVP

## 3. 产品定位建议

### 3.1 一句话定位

**OpenVideo 是一款好看、无广告、隐私友好、为本地与局域网视频优化的 Android 播放器。**

### 3.2 不建议走的方向

1. **不要做在线视频平台。** 版权、推荐、账号、内容运营会偏离项目优势。
2. **不要短期追求所有格式都自研解码。** 当前 Media3 + FFmpeg 音频扩展足够支撑 Android 主流视频体验；全量 FFmpeg/libmpv 化会带来体积、维护和许可复杂度。
3. **不要过早做云同步账号。** 先把本地身份、备份导入导出、局域网来源做好，再考虑账号。
4. **不要无限增加播放器按钮。** 功能已经不少，下一步重点应是信息架构、默认体验和手感。

### 3.3 差异化方向

1. **审美差异化：** 比 VLC/Nova 更现代，比 MX 更干净，比 Just Player 更有媒体库。
2. **本地追剧差异化：** 文件夹、剧集排序、继续观看、片头片尾、字幕自动匹配、海报墙。
3. **隐私差异化：** 无广告、无追踪、隐私文件夹、离线优先、权限最小化说明。
4. **专业但不复杂：** 高级播放能力藏在快捷面板/长按/设置中，默认体验保持简洁。

## 4. 新开发路线图

### Phase 0：稳定化与架构清债（1～2 周）

**目标：** 为后续大功能降风险，先把核心播放器职责继续拆薄。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P0-1 | PlayerActivity 继续瘦身 | 拆出字幕加载状态机、通知同步、手势分发、播放结束队列处理 | P0 |
| P0-2 | 播放错误体验 | 增加错误 HUD、重试/切换软解/复制诊断信息入口 | P0 |
| P0-3 | 设备兼容矩阵 | 建立编码、容器、字幕、HDR、蓝牙、后台播放测试清单 | P0 |
| P0-4 | 关键设置导入导出 | 先做本地 JSON 备份，不引入账号 | P1 |
| P0-5 | Release 门禁 | 固化 `testDebugUnitTest`、`assembleDebug`、`lintDebug` 的发布前检查 | P1 |

**验收标准：**

- PlayerActivity 单文件复杂度下降，新增能力优先落在 coordinator/policy/viewmodel。
- 播放失败时用户知道「为什么失败」和「能做什么」。
- 每次发布至少跑完核心单元测试、Debug 构建、Lint。

### Phase 1：播放器手感升级（2～4 周）

**目标：** 对齐 MX/Just/mpv 的高频播放体验，让播放器从「功能齐」变成「手感好」。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P1-1 | Pinch Zoom + Pan | 支持捏合缩放、拖动画面、双击恢复；与现有比例/取景框策略兼容 | P0 |
| P1-2 | Seek 缩略图预览 | 横向拖动进度时显示预览帧；先做本地文件，网络源后置 | P1 |
| P1-3 | 字幕手势 | 上下移动字幕、双指调字号、字幕延迟快捷 HUD | P1 |
| P1-4 | 双字幕模式 | 主字幕 + 第二字幕；先支持 SRT/VTT，ASS 样式后续增强 | P1 |
| P1-5 | 耳机/蓝牙策略 | 拔出暂停、蓝牙延迟提示、音频同步快捷入口 | P1 |
| P1-6 | 自动帧率匹配调研 | Android TV/盒子优先，手机默认关闭 | P2 |

**验收标准：**

- 纵屏/横屏/锁屏/PiP 下手势不冲突。
- 缩放、比例、旋转、镜像、字幕位置组合可恢复默认。
- 字幕调节能即时预览并持久化。

### Phase 2：媒体库体验升级（3～6 周）

**目标：** 从「文件列表」升级为「本地影视库」。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P2-1 | 文件身份稳定模型 | videoId + path + size + duration + modifiedTime 的多因子匹配，解决文件移动/重扫历史丢失 | P0 |
| P2-2 | 电影/剧集命名识别 | 解析 S01E02、EP02、第02集、分辨率、字幕组等文件名信息 | P0 |
| P2-3 | 剧集详情页 | 按剧名聚合季/集，展示继续观看、未看、已看完 | P1 |
| P2-4 | 本地海报缓存 | 支持同目录 poster/folder/cover 图片；后续再接 TMDb | P1 |
| P2-5 | 智能列表 | 最近添加、继续观看、未看完、已看完、大文件、4K/HDR、带字幕 | P1 |
| P2-6 | 播放列表重排 | 支持拖拽排序、批量移除、导入导出 M3U/JSON | P2 |

**验收标准：**

- 文件移动或重命名后，历史和收藏尽量不断链。
- 本地剧集能自动聚合，不依赖联网。
- 首页信息架构从「所有视频」升级为「继续观看 + 最近添加 + 文件夹/剧集」。

### Phase 3：网络与多来源播放（4～8 周）

**目标：** 从纯本地播放器扩展到局域网/NAS/URL，但仍保持离线优先。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P3-1 | 打开 URL | 支持 HLS/DASH/RTSP/普通 HTTP 视频地址，记录最近 URL | P0 |
| P3-2 | 网络流播放配置 | 缓冲策略、UA/Headers 基础配置、失败重试 | P1 |
| P3-3 | WebDAV 来源 | 先实现一个协议打通账号、浏览、播放、收藏 | P1 |
| P3-4 | SMB/NAS 调研与原型 | Android 端依赖、性能、字幕同目录发现 | P2 |
| P3-5 | DLNA/UPnP 投屏/浏览调研 | 先做技术可行性，不抢主线 | P3 |
| P3-6 | 来源管理页 | 本地、URL、WebDAV、未来 SMB/Jellyfin 等统一入口 | P1 |

**验收标准：**

- URL 播放和本地播放共享播放器体验、历史、字幕、音轨能力。
- 网络凭据安全存储，不明文散落在日志和崩溃报告。
- 网络失败有清晰状态：DNS/连接/403/404/解码/超时。

### Phase 4：字幕与内容增强（3～6 周）

**目标：** 把 OpenVideo 做成本地字幕体验强的播放器。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P4-1 | 字幕自动匹配 2.0 | 同目录、同名、语言后缀、Season/Episode 规则 | P0 |
| P4-2 | 在线字幕搜索 | OpenSubtitles 或兼容服务；先做手动搜索下载 | P1 |
| P4-3 | 字幕语言偏好 | 默认首选中文/英文/双语，按视频记忆 | P1 |
| P4-4 | ASS 样式增强 | 字体、描边、位置、简单特效兼容策略 | P2 |
| P4-5 | 字幕工具箱 | 延迟批量校正、编码转换、字幕另存为 | P2 |
| P4-6 | 双字幕 UI 打磨 | 主/副字幕字号、位置、颜色独立配置 | P1 |

**验收标准：**

- 用户打开剧集时，常见字幕无需手动选择。
- 字幕错位能在 2 次点击内完成修正。
- 在线字幕能力可关闭，隐私与网络请求透明。

### Phase 5：TV / 平板 / 遥控体验（4～8 周）

**目标：** 支撑 Android TV、平板横屏和客厅场景。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P5-1 | 大屏布局 | 平板/横屏首页双栏、播放器控制尺寸适配 | P1 |
| P5-2 | 遥控器焦点 | D-pad 焦点、返回/菜单/播放暂停/快进快退键 | P1 |
| P5-3 | TV 首页 | 最近观看、文件夹、来源、设置的 10-foot UI | P2 |
| P5-4 | 键盘快捷键 | 空格、方向键、J/K/L、字幕/音轨快捷键 | P2 |
| P5-5 | Android TV 发布准备 | Leanback icon、TV manifest、遥控测试、商店截图 | P3 |

**验收标准：**

- 不触屏也能完成浏览、播放、暂停、快进、切字幕、退出。
- 平板横屏不是简单拉伸，而是信息密度更高。

### Phase 6：品牌、发布与增长（并行推进）

**目标：** 让项目从个人工具走向可公开发布的产品。

| 编号 | 事项 | 说明 | 优先级 |
|------|------|------|--------|
| P6-1 | 品牌视觉 | 图标、启动页、空状态、商店截图、README 展示图 | P1 |
| P6-2 | 首次启动引导 | 权限说明、隐私承诺、扫描入口、基础手势教学 | P1 |
| P6-3 | 内置手势教程 | 播放页首次进入展示可跳过教程 | P1 |
| P6-4 | 发布渠道 | GitHub Release、F-Droid 可行性、Obtainium 说明 | P2 |
| P6-5 | 反馈入口 | 崩溃日志导出、GitHub Issue 模板、设备信息脱敏复制 | P2 |
| P6-6 | 隐私说明页增强 | 权限用途、网络请求、崩溃上报开关说明 | P1 |

**验收标准：**

- 新用户 1 分钟内理解权限、扫描、播放、手势。
- 发布包、版本说明、截图和隐私说明完整。

## 5. 推荐优先级排序

如果只选未来 6～8 周最值得做的 10 件事，建议如下：

1. **PlayerActivity 继续拆分与错误 HUD**：后续所有播放器能力的地基。
2. **Pinch Zoom + Pan**：竞品高频能力，和现有 P9-1b 取景方向一致。
3. **文件身份稳定模型**：解决历史、收藏、播放列表的根问题。
4. **剧集命名识别 + 剧集详情页**：把 OpenVideo 从列表工具升级为追剧工具。
5. **字幕自动匹配 2.0**：本地播放器体验提升最明显。
6. **打开 URL + HLS/DASH/RTSP**：补齐 Manifest 和 Media3 已具备但产品未闭环的能力。
7. **播放错误诊断与一键切软解**：降低「不能播」时的挫败感。
8. **Seek 缩略图预览**：提升播放器质感，但实现成本高于普通 UI。
9. **设置导入导出**：保护用户配置资产，也利于调试复现。
10. **首次启动/手势教程/品牌视觉**：为公开发布做准备。

## 7. 技术架构建议

### 7.1 继续强化的边界

| 边界 | 建议 |
|------|------|
| PlayerActivity | 只负责 View 绑定、生命周期转发、导航；播放策略继续迁到 policy/coordinator |
| PlayerManager | 只负责播放器内核、轨道、效果、截图/导出等底层能力；避免塞 UI 决策 |
| PlayerViewModel | 承接播放状态、当前视频、队列、历史、字幕状态；减少 Activity 局部状态 |
| Repository | 增加媒体身份解析、元数据缓存、来源抽象；避免 UI 直接拼数据 |
| Scanner | 保持 MediaStore 专注；网络/WebDAV/SMB 做独立 Source，不混进本地扫描器 |

### 7.2 新增模块建议

```text
core/mediaid/        文件身份、匹配、迁移策略
core/metadata/       文件名解析、本地海报、未来 TMDb 接口
data/source/         LocalMediaSource / UrlMediaSource / WebDavSource
core/network/        URL 探测、Headers、错误分类
ui/library/          剧集详情、智能列表、媒体详情
ui/onboarding/       首启引导、手势教程
```

### 7.3 数据表建议

| 表 | 用途 |
|----|------|
| `media_identity` | 保存稳定媒体身份、路径历史、size/duration/hash 片段 |
| `series` | 剧集聚合信息：标题、季、海报、本地目录 |
| `episodes` | 剧集单集映射：season、episode、videoId、观看状态 |
| `media_artwork` | 本地海报路径、生成缩略图、更新时间 |
| `media_sources` | URL/WebDAV/未来 SMB 来源配置 |
| `subtitle_cache` | 字幕文件、语言、来源、匹配置信度 |

## 8. 风险与取舍

| 风险 | 影响 | 建议 |
|------|------|------|
| 功能继续堆进 PlayerActivity | 后续难维护、易回归 | 每个播放器功能先设计 coordinator/policy，再接 UI |
| 网络来源过早铺太多协议 | 每个协议都半成品 | 先 URL，再 WebDAV，SMB/DLNA 延后 |
| 元数据联网引发隐私争议 | 和「隐私友好」定位冲突 | 默认离线；联网刮削需用户显式开启 |
| Seek 缩略图性能 | 大文件/低端机卡顿 | 先抽帧缓存 + 节流，提供关闭开关 |
| ASS/双字幕复杂度 | 样式兼容和布局冲突 | 先普通文本双字幕，再逐步增强 ASS |
| Android 版本和厂商差异 | PiP、通知、后台、解码表现不一 | 建机型/系统/编码回归表，保留降级策略 |

## 10. 结论

OpenVideo 当前最应该避免的是「再堆一堆按钮」。它已经有不错的播放器能力，下一阶段应该围绕三条主线推进：

1. **播放器稳定与手感：** 清债、错误诊断、缩放平移、字幕手势、缩略图预览。
2. **本地影视库体验：** 稳定身份、剧集识别、海报、智能列表、继续观看增强。
3. **多来源扩展：** URL/HLS/RTSP、WebDAV/NAS、字幕下载和来源管理。

如果执行顺序合理，OpenVideo 可以先成为一款「比 Just Player 更有媒体库、比 VLC 更好看、比 MX 更干净」的 Android 本地播放器，再逐步向 Infuse/Nova/Kodi 的媒体库和多来源能力靠近。
