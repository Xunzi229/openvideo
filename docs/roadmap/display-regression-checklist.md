# 播放器显示与智能裁边回归清单

**日期：** 2026-05-24  
**范围：** R-15 设备专项显示回归集；覆盖 R-04 智能裁边、手动缩放/平移、宽高比、横竖屏切换与播放器显示状态恢复。  
**触发时机：** 修改 `PlayerActivity` 显示链路、`PlayerContentFramePolicy`、智能裁边、手势缩放、宽高比、横竖屏布局、`PlayerView` / render view 采样路径后执行。

## 1. 测试前准备

| 项目 | 要求 |
|------|------|
| 构建包 | 使用当前分支 `:app:assembleDebug` 生成的 Debug APK |
| 设备 | 至少 1 台当前主力真机；如可用，再补 1 台不同 Android 大版本或不同厂商设备 |
| 主题 | 默认深色即可；如本次改动涉及浅色/控制层/弹窗，再补浅色主题 |
| 权限 | 媒体权限已授权；样本视频应能从首页或本地文件夹正常进入播放页 |
| 横屏入口 | 确认播放页可进入横屏，右侧浮动栏能看到智能裁边、倍速、宽高比、字幕、PiP 等入口 |
| 记录 | 每条记录设备型号、Android 版本、样本 ID、用例 ID、实际结果、是否通过 |

## 2. 样本矩阵

| 样本 ID | 类型 | 要求 | 主要验证点 |
|---------|------|------|------------|
| DISP-S01 | 普通横屏 16:9 | 无明显黑边，可正常播放 | 普通宽高比、手动缩放、智能裁边不可用降级 |
| DISP-S02 | 横屏四边黑边 | 真实内容窗口位于中间，上下左右都有明显黑边 | 智能裁边可用，内容约占视口 88%，不铺满 |
| DISP-S03 | 横屏非四边黑边 | 只有上下黑边、左右黑边或单边黑边 | 智能裁边不应触发，避免误裁真实内容 |
| DISP-S04 | 竖屏视频 | 9:16 或接近竖屏，普通短视频即可 | 竖屏不触发智能裁边，手动缩放仍可用 |
| DISP-S05 | 内置字幕/文字/卡片 | 视频内容中带底部字幕、顶部标题或边缘文字 | 智能裁边不能裁掉视频内置内容 |
| DISP-S06 | 极暗画面 | 主体很暗但不是黑边，最好有低亮度内容 | 黑边检测不过度把暗部内容当黑边 |
| DISP-S07 | 连续播放队列 | 同文件夹至少 2 个不同方向或不同比例视频 | 切歌时显示状态不串、不继承智能裁边 |

样本文件不要求提交到仓库。建议在本地测试目录保持稳定命名，并在结果记录中写明样本 ID 与简短特征。

## 3. 基础显示路径

| ID | 场景 | 步骤 | 期望 |
|----|------|------|------|
| DISP-BASE-001 | 普通横屏进入 | 打开 `DISP-S01`，进入横屏 | 视频居中显示；控制层位置正常；无异常裁切、偏移或黑屏 |
| DISP-BASE-002 | 普通竖屏进入 | 打开 `DISP-S04`，保持或切到竖屏 | 视频按竖屏显示；不会自动进入横屏智能裁边状态 |
| DISP-BASE-003 | 横竖屏切换 | 在同一视频内横屏、竖屏来回切换 2 次 | 画面不偏到左上角；控制层不重叠；字幕位置合理 |
| DISP-BASE-004 | 退出再进入 | 播放任一样本，退出播放页，再重新打开 | 显示状态回到普通会话默认；不残留上一轮智能裁边或平移状态 |
| DISP-BASE-005 | 切歌重置 | 使用 `DISP-S07` 连续播放下一集 | 新视频不继承上一视频的智能裁边；方向和比例按新视频重新计算 |

## 4. 智能裁边路径

| ID | 场景 | 步骤 | 期望 |
|----|------|------|------|
| DISP-CROP-001 | 四边黑边可裁 | 横屏打开 `DISP-S02`，点击 `btn_land_smart_crop` | 控制层先隐藏再检测；内容居中等比放大；目标内容约占视口 88%；显示 `player_smart_crop_applied` |
| DISP-CROP-002 | 再次点击关闭 | 在 `DISP-CROP-001` 成功后再次点击智能裁边 | 清除智能裁边和手动缩放状态；画面恢复普通显示；显示 `player_smart_crop_off` |
| DISP-CROP-003 | 非四边黑边不裁 | 横屏打开 `DISP-S03`，点击智能裁边 | 画面不放大；显示 `player_smart_crop_unavailable`；不裁掉边缘内容 |
| DISP-CROP-004 | 竖屏不裁 | 打开 `DISP-S04`，尝试触发智能裁边入口或切到竖屏后观察 | 竖屏不应用 `smartCropTransformOverride`；不出现智能裁边放大状态 |
| DISP-CROP-005 | 内置字幕保护 | 横屏打开 `DISP-S05`，点击智能裁边 | 视频内置字幕、标题、卡片或边缘文字仍可见；不追求铺满全屏 |
| DISP-CROP-006 | 极暗画面保守 | 横屏打开 `DISP-S06`，点击智能裁边 | 不把极暗主体误判成黑边；如无可靠建议则保持原画面 |
| DISP-CROP-007 | 会话状态隔离 | 对 `DISP-S02` 开启智能裁边，退出播放页，再重新打开同一视频 | 默认不处于智能裁边状态；必须由用户再次点击才启用 |

## 5. 缩放、平移与宽高比组合

| ID | 场景 | 步骤 | 期望 |
|----|------|------|------|
| DISP-ZOOM-001 | 手动缩放 | 打开 `DISP-S01`，双指放大到约 2x | 画面等比放大；无闪烁；字幕和控制层仍可读 |
| DISP-ZOOM-002 | 缩放后平移 | 在已缩放状态单指拖动画面 | 可平移但不出现异常空白边；松手后状态稳定 |
| DISP-ZOOM-003 | 双击恢复 | 缩放或平移后双击恢复默认画面 | 缩放和平移清零；普通双击播放/暂停配置不产生冲突或误触 |
| DISP-ZOOM-004 | 缩放后智能裁边 | 手动缩放 `DISP-S02`，再点击智能裁边 | 智能裁边会话接管显示状态；不会叠加出过度放大或偏移 |
| DISP-ZOOM-005 | 智能裁边后关闭 | 开启智能裁边后再关闭 | 智能裁边与手动缩放状态都被清除，画面回到普通显示 |
| DISP-ASPECT-001 | 宽高比切换 | 横屏依次切换适应、填充、16:9、4:3、裁切、拉伸 | 每个模式即时生效；切换过程中不残留智能裁边 override |
| DISP-ASPECT-002 | 智能裁边后宽高比 | 开启智能裁边后切换宽高比 | 行为可解释且稳定；若产品规则为切换后退出智能裁边，应恢复普通宽高比显示 |

## 6. 控制层与截图污染检查

| ID | 场景 | 步骤 | 期望 |
|----|------|------|------|
| DISP-UI-001 | 控制层隐藏后检测 | 横屏显示控制层时点击智能裁边 | 检测前控制层隐藏；按钮、标题、进度条不被当作视频内容 |
| DISP-UI-002 | Toast 不污染检测 | 连续触发智能裁边成功/不可用 Toast 后再次检测 | 新一轮检测前取消上一条智能裁边 Toast；Toast 不影响下一次内容边界判断 |
| DISP-UI-003 | 快捷弹窗互斥 | 打开宽高比/字幕/倍速弹窗后关闭，再触发智能裁边 | 弹窗不残留；智能裁边检测结果不受 UI 污染 |
| DISP-UI-004 | 锁屏状态 | 开启播放器锁屏后尝试显示/隐藏控制层，再退出锁屏触发智能裁边 | 锁屏期间不误触；退出锁屏后智能裁边入口仍正常 |
